# Design decisions

Each entry: the decision, the reason, and what was rejected. Newest last.

## D1. Python 3.12 with uv, src layout, strict mypy
uv gives a locked, reproducible environment that CI can install with `--frozen`. Strict mypy catches the shape errors that are common in eval code (dicts of metrics passed around). Python 3.12 because several observability packages cap below 3.15 and the brief rules out the system 3.14.

## D2. Gemini through the OpenAI-compatible endpoint
On this account the native `generateContent` endpoint returns 404 for current models, while `https://generativelanguage.googleapis.com/v1beta/openai/` serves them. LiteLLM talks to it as an OpenAI-compatible provider, so every model still goes through one provider layer.

## D3. Model roles
- Answer model (default): `gemini-3.8-flash`, the newest Gemini model with free quota on this key.
- Judge: `openai/gpt-oss-120b` on Groq, a different model family from every answer model under test (Gemini, Qwen), so the judge is never grading its own family.
- Comparison models: `gemini-3.8-flash`, `qwen/qwen3.8-27b` on Groq, local `qwen3:8b` on Ollama.
- Groq's 8000 tokens per minute cap means agent prompts must stay compact; the judge prompt is short, which is why the judge lives on Groq.

## D4. JSON-file response cache keyed on the full request
Every LLM request (model, messages, tools, sampling parameters, provider extras) is hashed with SHA-256 and the response is stored as one JSON file. Files instead of SQLite so the slice the CI gate replays can be committed and read in a diff. `LLM_MODE=replay` serves only from the cache and raises `CacheMissError` on a miss, which is what makes the CI gate deterministic, free and keyless. Replays report the latency recorded live, so latency metrics do not collapse to zero on replay.

## D5. List-price-equivalent cost
Each model carries its public list price per million tokens (checked 2026-11-01): Gemini 3.8 Flash $0.75 in / $3.75 out (Google's introductory rate through 2026-12-31, per several pricing trackers; Google's own page is ai.google.dev/gemini-api/docs/pricing), GPT-OSS 120B on Groq $0.15 / $0.60, Qwen3.8 27B on Groq $0.80 / $4.00 (preview rate). Local qwen3:8b has no list price and is priced at $0. Gemini's OpenAI-compatible endpoint reports thinking tokens only in `total_tokens`, so billable output is `total - prompt`; ignoring that would under-count Gemini cost by an order of magnitude on short answers.

## D6. Retries without silent fallback
Retries use exponential backoff with jitter (up to 8 attempts, 90 s cap) on rate limits, 5xx and connection errors, never on auth or bad-request errors. There is deliberately no automatic fallback to another model: a fallback would silently mix models inside one run and corrupt model comparisons. Client-side pacing keeps each model under its free-tier requests-per-minute.

## D7. Retrieval layout: SQLite for text, Qdrant for vectors, bm25s for keywords
Chunk text and metadata live in one SQLite file keyed by chunk id; Qdrant stores only vectors plus the filterable fields (ticker, year, form, filing, doc), and BM25 stores ids plus a metadata array. Every consumer that needs a passage (citations, `get_table`, the UI) reads it from SQLite, so the API container never holds the corpus in memory. BM25 filtering scores the whole corpus and masks it rather than filtering a top-N, so narrow filters never come back short. Hybrid uses reciprocal rank fusion (k = 60, the value from Cormack et al. 2009) over the top 40 of each retriever; the optional rerank is `Xenova/ms-marco-MiniLM-L-6-v2` through fastembed's ONNX runtime, which avoids pulling torch into the image. Embedding is resumable: a chunk is re-embedded only when its text hash changes. Measured embedding throughput with `nomic-embed-text` on the M-series host: about 19 chunks per second for ~500-token chunks.

## D-MCP: MCP server on protocol 2026-07-28, stdio first, streamable HTTP second
The server uses the official SDK's `MCPServer` (mcp 2.3), which speaks protocol revision 2026-07-28, the newest the SDK knows (`LATEST_PROTOCOL_VERSION`). That revision drops the `initialize` handshake for a stateless per-request envelope that clients discover with `server/discover`, so the server needs no session state and the same tool code works over any transport. The SDK still answers `initialize` for older clients (it negotiates 2025-11-25), and a test pins that, because desktop clients move to new revisions on their own schedule. Stdio is the default transport because the main client, Claude Desktop or an IDE, launches the server locally with `uv --directory <repo> run ledgerlens mcp serve`: no port, no auth, and the index never leaves the machine. Streamable HTTP (`--transport http`) is there for multi-client use and binds to 127.0.0.1, where the SDK enforces Host and Origin checks. It has no auth, so a non-loopback bind is refused unless the operator passes `--allow-remote` with an explicit `--allowed-host` list (which feeds the same DNS rebinding checks), and `ask` is then off unless `--ask` is passed, since each call spends LLM quota; a real remote deployment still needs an authenticating reverse proxy. The deprecated SSE transport is not offered. The tools wrap the agent's own functions (retrieval, companyfacts, the AST calculator) and skip the agent's tool cache: that cache exists so eval runs can be recorded and replayed in CI, while MCP clients are interactive and never replayed, so there is nothing worth recording. Tool errors carry fixed messages for the failures we expect and never raw exception text, which can hold paths, hosts or provider account details. All tools are marked read-only; `get_company_facts` and `ask` are also marked open-world because they can reach SEC or an LLM provider. `ask` can be hidden with `--no-ask` for clients that should only see the free, deterministic tools.

## D11. Chat streams agent steps live and the answer after the run
`POST /api/chat` runs the synchronous LangGraph agent in a small dedicated thread pool (one worker per allowed concurrent chat, `MAX_CONCURRENT_CHATS`, default 2, so free-tier quotas are not burned by parallel tabs) with a copy of the request's contextvars, which carry usage tracking and tracing. Each `on_step` callback is pushed onto an asyncio queue with `call_soon_threadsafe`, so steps reach the browser as they happen. The answer is not token-streamed from the model: the agent's answer only exists after verification and the citation self-check may rewrite it or turn it into a refusal, so streaming raw model tokens would show text that is later retracted. The final, checked text is sent as small `token` events and then the full `answer`. When the client disconnects, the next `on_step` call raises inside the agent thread, so an abandoned question stops spending LLM calls at the next step. Errors reach the UI as a short, fixed message per error type; the exception text stays in the server log.

## D12. XBRL citations get a synthesized chunk
Citations of XBRL facts carry ids like `xbrl:KO:NetIncomeLoss:2025-01-01_2025-12-31:USD`, which are not in the chunk store. `GET /api/chunks/{id}` parses the id, looks the fact up in the cached SEC companyfacts file and returns a Chunk whose text is a small Markdown table (value, period, filing, accession), so the source panel works the same for passages and facts. If companyfacts cannot be read, the chunk is built from the id alone and says the value could not be loaded; an id that parses but matches no fact is a 404. The route uses a `path` parameter because units such as `USD/shares` contain a slash.

## D13. Fixed Docker Compose project name
`docker-compose.yml` sets `name: ledgerlens`. Without it Compose derives the project from the folder name, so a second clone or a git worktree would create a parallel Qdrant and Phoenix with empty volumes (and fail on the already bound ports) instead of reusing the indexed ones.
